# 하루메일 UI/UX Implementation Plan

**Goal:** 한국 이용자가 바로 주소를 만들고 복사하고 메일을 읽는 일관된 무료 메일 앱으로 전면 개편한다.

**Architecture:** 기존 정적 빌드와 서버 API를 유지한다. `index.html`은 메일 앱 구조, `styles.css`는 전체 디자인, `scripts/build.js`는 공통 메뉴와 콘텐츠 레이아웃을 맡고 `app.js`는 상태와 사용자 행동을 처리한다.

**Tech Stack:** Node.js, 정적 HTML/CSS, 브라우저 JavaScript, node:test.

- [x] `tests/concurrency.test.js`의 DOM 대역에 필요한 이벤트·포커스·속성 모델을 추가한다. 실제 행동을 검증하는 실패 테스트: 구성 조회 재시도, 인증번호 복사 거절 후 올바른 텍스트 선택, 상세 화면 목록 복귀, 백그라운드 목록 갱신의 포커스 보존.
- [x] `index.html`, `styles.css`, `favicon.svg`, `scripts/build.js`를 개편한다. 공통 메뉴, 주소 카드, 상태 배지, 단일 받은편지함, 가이드 카드와 읽기 페이지를 한 디자인으로 적용한다. 휴대폰에서는 메뉴와 카드가 한 열로 흐른다.
- [x] `app.js`에 준비/오류 상태, 수동 재시도, 복사 피드백과 수동 복사 대화상자, 상세 복귀를 구현한다. 기존 revision 검증을 보존한다. 수신 목록이 변하지 않으면 DOM을 교체하지 않는다.
- [x] 전체 빌드와 테스트를 순서대로 실행한다. 생성 HTML의 내부 링크·ID 참조·메타데이터·외부 스크립트 경계를 점검한다. 별도 코드 리뷰에서 발견된 관련 문제를 수정한다.
- [ ] 기존 GitHub PR에 반영하고 Vercel 미리보기 성공을 확인한다. 배포용 ZIP과 현재 출시 준비 상태를 갱신한다. 미리보기와 정식 출시를 명확히 구분해 보고한다.

- [x] 출시 검토에서 확인한 HTML 인증 링크 누락과 1,000개 이후 조회 중단을 수정했다. 텍스트 변환에서 안전한 HTTP(S) URL을 보존하고, 메일함별 서명 조회 커서로 나누어 수신 목록을 이어서 조회한다. 위조·다른 메일함 커서의 API 진입 차단도 검증한다.
